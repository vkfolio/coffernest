At home, the app can talk to your server over plain HTTP. To use it on mobile data or at work, give the server a domain name with HTTPS by putting a reverse proxy in front of it.

## Why the iPhone needs HTTPS

iPhone apps follow Apple's App Transport Security, which only allows encrypted connections with a certificate the phone trusts. Coffernest asks for one exception: plain HTTP to addresses on your local network, such as `http://192.168.1.20:8080` or `http://homeserver.local:8080`. The first time, iOS asks whether Coffernest may connect to devices on your local network; tap **Allow**.

Any other address needs `https://` and a valid certificate, for example a free one from Let's Encrypt. A self-signed certificate won't work.

## Two addresses, not one

The server is reached at two places, and both need HTTPS when you're away from home:

- The API, on port 8080. Its public address goes in `PUBLIC_URL`, and it's what you type in the app.
- MinIO, on port 9000. Its public address goes in `S3_PUBLIC_URL`. The app opens bills and statements from there directly, using links the server signs for that address.

Give each one its own host name, for example `money.example.com` and `files.example.com`, both pointing at your server.

## Set up the proxy

<Tabs>
<TabItem label="Caddy">
Caddy gets and renews certificates by itself. With Caddy running on the same machine, this `Caddyfile` is enough:

```text
money.example.com {
	reverse_proxy localhost:8080 {
		header_up X-Real-IP {remote_host}
	}
}

files.example.com {
	reverse_proxy localhost:9000
}
```

Then in `.env`:

```bash
PUBLIC_URL=https://money.example.com
S3_PUBLIC_URL=https://files.example.com
TRUSTED_PROXY_HEADER=X-Real-IP
```
</TabItem>
<TabItem label="nginx">
nginx needs a larger upload limit (its default is 1 MB) and no buffering, so the assistant's replies and live updates arrive as they're written. Certificates are up to you, for example with Certbot.

```nginx
server {
    listen 443 ssl;
    server_name money.example.com;
    # ssl_certificate and ssl_certificate_key here
    client_max_body_size 200m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}

server {
    listen 443 ssl;
    server_name files.example.com;
    # ssl_certificate and ssl_certificate_key here
    client_max_body_size 30m;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_set_header Host $host;
    }
}
```

Then set `PUBLIC_URL`, `S3_PUBLIC_URL` and `TRUSTED_PROXY_HEADER=X-Real-IP` as in the Caddy tab.
</TabItem>
<TabItem label="Traefik or Coolify">
If Traefik already runs on the machine, add labels to the `api` and `minio` services in `docker-compose.yml`. The entry point and certificate resolver names (`websecure`, `letsencrypt`) must match your Traefik setup.

```yaml
  api:
    labels:
      - traefik.enable=true
      - traefik.http.routers.coffernest.rule=Host(`money.example.com`)
      - traefik.http.routers.coffernest.entrypoints=websecure
      - traefik.http.routers.coffernest.tls.certresolver=letsencrypt
      - traefik.http.services.coffernest.loadbalancer.server.port=8000
  minio:
    labels:
      - traefik.enable=true
      - traefik.http.routers.coffernest-files.rule=Host(`files.example.com`)
      - traefik.http.routers.coffernest-files.entrypoints=websecure
      - traefik.http.routers.coffernest-files.tls.certresolver=letsencrypt
      - traefik.http.services.coffernest-files.loadbalancer.server.port=9000
```

The containers must share a Docker network with Traefik. In Coolify, deploy the compose file as a Docker Compose resource and give the `api` service your domain on port 8000 and `minio` a second domain on port 9000. Traefik passes the visitor's address as `X-Real-IP`, so set `TRUSTED_PROXY_HEADER=X-Real-IP`.
</TabItem>
<TabItem label="Cloudflare">
With a Cloudflare Tunnel, `cloudflared` connects out from your machine, so you open no ports. Add two public host names to the tunnel: `money.example.com` to `http://localhost:8080` and `files.example.com` to `http://localhost:9000`. If `cloudflared` runs in the same compose project, use `http://api:8000` and `http://minio:9000` instead.

The same applies if you point proxied DNS records at your server. Either way, Cloudflare sends the visitor's address in `CF-Connecting-IP`:

```bash
PUBLIC_URL=https://money.example.com
S3_PUBLIC_URL=https://files.example.com
TRUSTED_PROXY_HEADER=CF-Connecting-IP
```

Cloudflare limits the size of one upload on its smaller plans (100 MB on Free). Restoring a backup larger than that won't get through; restore it over your home network instead.
</TabItem>
</Tabs>

After editing `.env`, recreate the API container:

```bash
docker compose up -d --force-recreate api
```

Tailscale works too. Names under `ts.net` aren't local addresses to iOS, so use `tailscale serve` (or Funnel) with HTTPS rather than plain HTTP.

## The visitor's address

Sign-in lockouts count failed attempts per IP address, and **Signed-in devices** shows where each device signed in from. Behind a proxy, every request seems to come from the proxy, so one person's typos could lock out the whole family. `TRUSTED_PROXY_HEADER` tells the server which header holds the real address.

<Aside type="caution">
Set `TRUSTED_PROXY_HEADER` only when every request goes through that proxy. If port 8080 can still be reached directly, anyone could send the header themselves and choose the address they're counted under. When the proxy runs on the same machine, publish the ports on localhost only, in `docker-compose.yml`:

```yaml
    ports: ["127.0.0.1:8080:8000"]
```

and the same for MinIO (`"127.0.0.1:9000:9000"`).
</Aside>

## Check it and switch the app over

<Steps>

1. From outside your network (for example on mobile data), open `https://money.example.com/health`. You should see `{"ok":true,"db":true,"s3":true}`.

2. In the app, go to **Settings › Server** and tap **Change server**.

3. Enter `money.example.com`. The app adds `https://` for you. Tap **Check connection**, then **Save**, and sign in again.

</Steps>

Changing the server address signs you out of the old one. Your books stay on the server; only the address changes.
