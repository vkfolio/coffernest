Paths below are relative to `https://your-server/api/v1` unless they start with a different root. For request and response fields, open `/api/v1/docs` on your server.

In the **Who** column, "Member" means any signed-in member, "Owner or adult" excludes viewers, and "Owner" is the household owner only. "Public" needs no sign-in.

## Sign-in and account

| Method | Path | What it does | Who |
|---|---|---|---|
| POST | `/auth/register` | Create an account and sign in | Public |
| POST | `/auth/login` | Sign in with email, password and, if needed, a two-step code | Public |
| POST | `/auth/refresh` | Swap a refresh token for a new pair of tokens | Public |
| POST | `/auth/logout` | End this session | Public |
| POST | `/auth/logout-all` | End every session for the account | Member |
| GET | `/auth/me` | Your account | Member |
| DELETE | `/auth/me` | Delete your account for good (and the household, if nobody else is in it) | Member |
| GET | `/auth/sessions` | Signed-in devices | Member |
| DELETE | `/auth/sessions/{family_id}` | Sign one device out | Member |
| POST | `/auth/password` | Change your password | Member |
| POST | `/auth/totp/setup` | Start two-step sign-in: secret and `otpauth://` link | Member |
| POST | `/auth/totp/confirm` | Confirm two-step sign-in with a code; returns recovery codes | Member |
| POST | `/auth/totp/disable` | Turn two-step sign-in off | Member |

## Assistant

| Method | Path | What it does | Who |
|---|---|---|---|
| GET | `/ai/status` | Whether AI is set up, on for the household, and which model | Member |
| GET | `/ai/suggestions` | The latest monthly suggestions | Member |
| POST | `/ai/suggestions/refresh` | Make new suggestions (once every 10 minutes) | Owner or adult |
| POST | `/ai/suggestions/{suggestion_id}/dismiss` | Hide a suggestion | Owner or adult |
| POST | `/ai/suggestions/{suggestion_id}/feedback` | Mark a suggestion helpful or not | Member |
| POST | `/ai/ask` | One question, one answer, with checked amounts | Member |
| GET | `/ai/threads` | Conversations, newest first (`q` searches them) | Member |
| POST | `/ai/threads` | Start a conversation | Member |
| GET | `/ai/threads/{thread_id}` | A conversation with its messages | Member |
| PATCH | `/ai/threads/{thread_id}` | Rename a conversation | Member |
| DELETE | `/ai/threads/{thread_id}` | Delete a conversation | Member |
| POST | `/ai/threads/{thread_id}/messages` | Send a message; the reply streams back as server-sent events | Member |
| POST | `/ai/actions/undo` | Undo a change the assistant made | Owner or adult |

The message stream sends `meta`, `status` (a tool being used), `token` (text as it is written), `block` (an action card or roadmap), `done` (the saved message, with `verified` and `unverified_amounts`) and `error` events. A message can include up to 5 inbox file ids in `attachments`.

## Connections

| Method | Path | What it does | Who |
|---|---|---|---|
| GET | `/connections` | The MCP address, your API tokens and connected apps | Member |
| POST | `/connections/tokens` | Make an API token with a `name` and `access` of `read` or `write`. The token is returned once. | Owner or adult |

## Outside the API

These are not in the OpenAPI schema.

| Method | Path | What it does |
|---|---|---|
| POST | `/mcp` | The MCP endpoint for connected apps |
| GET | `/.well-known/oauth-protected-resource` | Which sign-in server protects `/mcp` |
| GET | `/.well-known/oauth-authorization-server` | Sign-in server details (also at `/.well-known/openid-configuration`) |
| POST | `/oauth/register` | Register a connecting app |
| GET, POST | `/oauth/authorize` | The sign-in page connected apps open |
| POST | `/oauth/token` | Exchange a sign-in code, or renew access |
| POST | `/oauth/revoke` | Revoke a connected app's token |
| GET | `/privacy`, `/terms`, `/support` | This server's privacy policy, terms and support page |

<Aside type="note">
Routes act on the signed-in member's household only. An id from another household answers `404`, as if it didn't exist.
</Aside>
